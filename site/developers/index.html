Messages++ API

Send texts from your own phone and number, from your website, shop or system.

Overview

The API doesn't send texts from a shared gateway. Each message is queued for your phone running Messages++, which sends it from your SIM and number and reports back. People who are on Contacts++ and accept messages from you get a free Contacts++ chat instead of a text.

  • Who can use it: members with Contacts++ Premium (or a Business plan). Keys are made in the web app, never in the phone app.
  • What you need: Messages++ on an Android phone, signed in with the same Contacts++ account, with automatic sending set up. An iPhone can also take API messages, but asks you to tap Send for each text.
  • Base URL: https://s1199.comeriver.com/api/v1/gateway

Quickstart

  1. Sign in to Messages++ on the web with Contacts++, open API and create a key. Copy the key and the webhook secret: they're shown once.
  2. On your phone, sign in to Messages++ with the same account.
  3. Send your first message:
curl https://s1199.comeriver.com/api/v1/gateway/messages \
  -H "Authorization: Bearer $MESSAGES_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"to": "+2348030000000", "body": "Your order #42 is ready for pickup.", "reference": "order-42"}'

The answer is 202 Accepted: the message is queued and your phone is woken to send it, usually within seconds.

Authentication

Send your key as a Bearer token: Authorization: Bearer mpk_live_…. Keep it on your server; never put it in a website, an app or a public repository. If a key leaks, revoke it in the web app and make a new one.

A key can be limited to your server's IP addresses (single addresses or ranges such as 203.0.113.0/24). Requests from anywhere else get 403 ip_not_allowed.

Sending messages

POST /gateway/messages

FieldDescription
toThe number, ideally in international format (+2348030000000). Local numbers need country.
bodyThe text, up to 1,600 characters. Long texts go as several SMS parts.
referenceOptional, your own id (up to 100 characters). Sending again with the same reference within 24 hours returns the first message instead of sending a second one, so retries are safe.
messagesInstead of to/body: a list of up to 100 {to, body, reference}.
countryOptional two-letter country for local numbers, e.g. NG.
phone_idOptional: which of your phones sends it (see Choosing a phone).
send_atOptional ISO 8601 time within the next 7 days, to send later.

GET /gateway/messages/{id}

The message's current status. Prefer webhooks to polling; if you poll, every 30 seconds or slower.

Statuses

StatusMeaning
queuedWaiting for your phone.
claimedYour phone has it and is sending it.
sentYour phone sent it. channel says how: sms or chat (Contacts++).
deliveredThe carrier confirmed delivery (not every carrier reports this).
failedIt couldn't be sent; see error_code.
opted_outThis person opted out of your messages, so it wasn't sent.
expiredNo phone picked it up within 24 hours (phone off, signed out, or no connection).
cancelledCancelled in the web app before it was sent.

Webhooks

Give your key a public https webhook URL and Messages++ POSTs every status change to it:

POST /your-webhook
X-Messages-Event: message.sent
X-Messages-Signature: t=1762855200,v1=5f2b…

{ "event": "message.sent", "id": "evt_1234", "created_at": "2026-11-11T10:00:05+00:00",
  "data": { "id": "01933a…", "batch_id": "9f1c…", "to": "+2348030000000", "reference": "order-42",
            "status": "sent", "channel": "sms", "error_code": null } }

Answer with any 2xx within 10 seconds. Anything else is retried after 1, 2, 4, 8… minutes, up to 8 times. Events can arrive more than once or out of order: use data.status and ignore an id you've already handled.

Check the signature

The signature is an HMAC-SHA256, with your webhook secret, of <t>.<raw body>. Compare it in constant time and refuse timestamps older than 5 minutes.

import crypto from 'node:crypto';
import express from 'express';

const app = express();
app.post('/messages-webhook', express.raw({ type: 'application/json' }), (req, res) => {
  const header = req.get('X-Messages-Signature') || '';
  const { t, v1 } = Object.fromEntries(header.split(',').map(p => p.split('=')));
  const expected = crypto.createHmac('sha256', process.env.MESSAGES_WEBHOOK_SECRET)
    .update(`${t}.${req.body}`).digest('hex');
  const fresh = Math.abs(Date.now() / 1000 - Number(t)) < 300;
  if (!fresh || !v1 || !crypto.timingSafeEqual(Buffer.from(v1), Buffer.from(expected))) {
    return res.sendStatus(400);
  }
  const event = JSON.parse(req.body);
  // e.g. mark order event.data.reference as texted
  res.sendStatus(204);
});
$body = file_get_contents('php://input');
parse_str(str_replace(',', '&', $_SERVER['HTTP_X_MESSAGES_SIGNATURE'] ?? ''), $sig);
$expected = hash_hmac('sha256', ($sig['t'] ?? '') . '.' . $body, getenv('MESSAGES_WEBHOOK_SECRET'));
if (abs(time() - (int) ($sig['t'] ?? 0)) > 300 || ! hash_equals($expected, $sig['v1'] ?? '')) {
    http_response_code(400);
    exit;
}
$event = json_decode($body, true);
// e.g. update order $event['data']['reference']
http_response_code(204);

from flask import Flask, request, abort

app = Flask(__name__)

@app.post("/messages-webhook")
def messages_webhook():

    expected = hmac.new(os.environ["MESSAGES_WEBHOOK_SECRET"].encode(),
                        f"{parts.get('t', '')}.".encode() + request.get_data(), hashlib.sha256).hexdigest()
    if abs(time.time() - int(parts.get("t", 0))) > 300 or not hmac.compare_digest(expected, parts.get("v1", "")):
        abort(400)
    event = request.get_json()

Rotate the secret any time in the web app (↻ Secret); the old one stops working at once.

Choosing a phone

GET /gateway/phones lists your phones signed in to Messages++:

{ "data": { "phones": [ { "id": "4b0d…", "name": "Messages++ on Android", "platform": "android",
  "sends_automatically": true, "last_seen_at": "2026-11-11T09:58:00+00:00" } ] } }

Without phone_id (on the request or the key), any of your phones may send it. Set one so texts always leave from the same number.

Errors

Errors have "success": false and an errors list with a code and a readable message. Field problems come back as 422 with errors.<field>.

HTTPcodeWhat to do
401invalid_api_keyCheck the key; it may have been revoked.
402premium_requiredContacts++ Premium has ended. Renew it.
403ip_not_allowedCall from an allowed IP address or update the key.
422(fields)Fix the request. With no phone signed in, phone_id says so.
429rate_limitedWait for Retry-After seconds.
429daily_limit_reachedThe key's daily limit is used up; raise it in the web app or wait until tomorrow (UTC).

Limits

  • 60 requests a minute per key; up to 100 messages per request.
  • A daily limit per key (500 to start, up to 5,000), set in the web app.
  • Your phone also keeps its own send limits and delay between texts (Messages++ › Settings › Sending safely), so carriers don't block your SIM.
  • Messages wait up to 24 hours for a phone; then they expire.

With Contacts++

Contacts++ uses the same service: when you send invitations or outreach from Contacts++ and choose Send from my phone, they go through Messages++ on your phone, and you follow them under Sends. People already on Contacts++ get a chat; everyone else gets a text from your number with your invitation link.

Signing in elsewhere with your Contacts++ account never shares your password: each app gets its own, limited permission, which you can remove in Contacts++ › Settings › Devices.

Good practice

  • Only text people who asked to hear from you, and say who you are.
  • Honour opt-outs. Replies such as STOP reach your phone; numbers you mark as opted out in Messages++ are never texted (opted_out).
  • Texts go from a personal SIM. Many carriers limit or forbid bulk or business traffic on personal lines: check your carrier's terms and local rules (for example, in Nigeria, the NCC's rules on unsolicited messages).
  • Don't send one-time passwords or anything secret through a personal phone.
